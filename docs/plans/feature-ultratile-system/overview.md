# Introduction

![Status: Planned](https://img.shields.io/badge/status-Planned-blue)

Build UltraTile end-to-end from empty repo (`README.md:1`, `project_instructions.md:1-94`). JDK-only Java 21 `ServerSocketChannel` server bound to loopback by default (trusted-LAN/demo scope; `--bind` opts into `0.0.0.0`), reader VT + dispatcher VT per WS session, `WsWriter` on `ReentrantLock` with `writeFully`, `transferTile` declaring `24+fileSize` with bounded zero-progress positional fallback, mid-frame failure fatal; `closeSession()` wakes BOTH threads (socket close + permit release; dispatcher checks `closed` on wake). Serves frontend over a strict HTTP/1.1 subset (generic-`method` lexical grammar per RFC 9112, multi-value header map, singleton WS headers, absolute-form authority MUST equal Host under a frozen http-only profile, body-framing gate BEFORE the GET-only method gate, duplicate `Content-Length` always 400) and padded 512x512 JPEG tiles over sealed-generation UTP/1.0 on RFC 6455 with mandatory subprotocol `ultratile.utp.v1`. Generation history is monotonic `lastReqIdSeen`, advanced ONLY on accepted new generations; STALE messages are ignored but semantically ILLEGAL current-client messages deterministically close with 1002 (a rejected reqId is remembered — never later accepted: every new-generation chunk/COMMIT first checks `rejectedReqIds`, entries are purged only once stale, and the connection closes rather than evict a live entry). COMMIT builds the immutable `work` list off-queue, attaches it, seals last, then publishes ONE coalesced ready slot — including empty COMMITs (`work=List.of()` through the same dispatcher path); dispatcher walks `work` with local `nextIndex`, END iff drained. LOD 0 (nearest) is the only implemented mode, FORMAT 1 (JPEG) the only implemented format. u32 wire fields parse to `long`. Client opens its socket with the mandatory subprotocol and owns each coordinate through needed → pending-network → received → cached with epoch cleanup on EVERY intent, `receivedKeys` network bookkeeping (visual coverage tracked separately), and `BatchState` lifetime rules; batches are headroom-gated with dynamic sizing. Demos per-ID (0 and 1 independently ensured) via atomic `.ready` publish plus a bounded pre-decode-capped JDK `ImageIO` real-image fallback; canonical `level-Z/X_Y.jpg` tile pathnames shared by all importers; strict bounded `meta.json`; live rescan. Two-track testing: the authoritative JDK-only build/runtime path (`build.sh`, clean-machine) versus the offline validation path (Python/Node optional test tooling; Maven/JUnit are primed-cache development tests). ## 1. Requirements & Constraints

- **REQ-001**: Java 20/21 async server serves ultra-high-resolution images with progressive/selective loading via 512x512 tiling (ceiling pyramid, post-padded edges, clear-then-clip compositing); never serves full ultra-res image.
- **REQ-002**: Per WS session one reader VT + one dispatcher VT; one serialized `WsWriter` (`ReentrantLock`; reader may call `writeControl` under it); blocking-on-VT model (NOT selector async; report states plainly). Visibility: `AtomicReference<GenerationState> active`, `AtomicLong lastReqIdSeen` (reader-updated ONLY on accepted new generation — first valid chunk OR valid empty COMMIT even with an older active present; same-gen chunks, matching COMMITs, ABORTs, rejects never advance; anything below it is stale unless the active generation's allowed continuation), `volatile` sealed/canceled, `AtomicBoolean` closed, teardown-only atomic tile-channel ref, idempotent cleanup; dispatcher owns `sent/skipped/inFlight` + local `nextIndex`; requested set reader-owned pre-seal. Frozen teardown/wakeup: `closeSession()` atomically sets `closed`, closes the socket (wakes a blocked reader), AND releases the dispatcher permit (wakes `readyPermit.acquire()`); the dispatcher checks `closed` immediately after every wake and exits without emitting; a dispatcher-side fatal I/O closes the socket which wakes the reader. Cancellation is frame-boundary/best-effort: ABORT/supersession NEVER close the current tile channel — an already-started TILE finishes, then the dispatcher observes `canceled`; a stale complete TILE may still arrive (client discards via `classify`). Active-clearing (frozen): dispatcher CAS-clears `active` iff still its state after sending END — the ONLY lifecycle that clears an active sealed generation, including sealed-empty ones; reader CAS-clears iff still the ABORT-matched state; supersede overwrites. Close coordination as v1.6; I/O/EOF aborts immediately. No deadlines by design. Transport decision is isolated to `net/`+`ws/` — tile store, UTP packets, session rules, viewer survive a selector/`AsynchronousServerSocketChannel` swap.
- **REQ-003**: Strict HTTP/1.1 subset: request line `method SP target SP HTTP/1.1` with `method = token` (generic, per RFC 9112 — NOT literal `GET`; unknown methods parse lexically and die at the method gate), `Allow: GET` on 405, origin-form + absolute-form under a frozen profile (plain `http` scheme only, no userinfo, no fragment, normalized host/IP-literal plus optional numeric port; authority MUST equal the single Host value else 400 — a DELIBERATE restriction vs RFC 9112 authority-replacement, documented as such in the protocol report), exactly-one valid Host, headers stored as `Map<String,List<String>>` (multiplicity preserved; duplicates detected before collapsing), strict LEXICAL grammar (exact CRLF — bare LF →400; single SP separators — extra/missing whitespace →400; any version token ≠ `HTTP/1.1` →400 documented subset simplification, no 505; empty target →400; header lines `field-name ":" OWS field-value OWS` — name MUST be RFC 9110 `token`, whitespace BEFORE `:` →400, empty name →400, missing `:` →400; lines starting SP/HTAB (obs-fold) →400; NUL/CTL in names or values →400; only OWS trimmed from values; `Content-Length` strict ASCII-decimal with overflow detection), FROZEN gate order — lexical parse → header/Host validation → GLOBAL body-framing gate (any `Transfer-Encoding` →400 on ALL routes; any `Content-Length` ≠0 →400; DUPLICATE `Content-Length` →400 even when values agree; single `Content-Length: 0` allowed, no body follows) → method gate (`!=GET` → `405` + `Allow: GET` + close) → target routing — so bodyless POST gets 405 but POST+body/TE gets 400, `writeFully`/`readFully`, leftover bytes only after bodyless valid upgrade (else close+discard — no pipelining); API JSON serialized through one shared `jsonEscape()` routine; UTP/1.0 over RFC 6455 documented.
- **REQ-004**: Frontend locally served, offline; `resizeCanvas()` DPR=1 first; drag/wheel pointer-anchored within scales + `isFinite` + capture/`pointercancel`; immediate cached render + debounced network intent (new `viewEpoch` per intent). Node (`node --check`, `test_viewer.cjs`) is TEST-ONLY tooling: the shipped app (Java + static JS, no build step) never requires Node; E2E/manual validation paths without Node are documented in the report.
- **REQ-005**: LOD frozen (`zFloat`, clamp, ceil/floor/frac≥0.5); `effectiveLOD` per-Z recompute, union ≤36; HUD desired-vs-effective; clear-then-clip full-bitmap compositing.
- **REQ-006**: LRU-40; Z0 pinned; intermediates opportunistic; decode ≤6 in-flight + queue jobs≤24 AND bytes≤4MiB (distinct names); per-intent `viewEpoch`; `BatchState{reqId,epoch,imageId,zoom,expectedKeys:Set,receivedKeys:Set,networkComplete,canceled}` with FROZEN lifetime (reclaim a current-epoch state when `networkComplete && decodeRefs==0`; retain canceled previous-epoch states only while that epoch is the immediate predecessor — a third epoch drops them); every received TILE's `(image,z,x,y)` MUST be in `expectedKeys` with matching image/zoom else discard+counter; DUPLICATE TILE for an already-`receivedKeys` key → drop + `dupTiles++` (wire bytes still counted; no second decode); valid END MUST satisfy `sent + skipped == expectedKeys.size()` else `endCountMismatch++` + reconcile from `receivedKeys`; END's `(imageId,reqId)` MUST match a live batch — a wrong-image END is PROTOCOL-FATAL (close the socket / fail the client) so no waiter can hang. `receivedKeys` is STRICTLY network bookkeeping (receipt + duplicate detection); visual coverage is tracked separately: `netCov = received + serverSkipped` (network done-ness) vs `covCov = cached target keys / needed target keys` (what is actually on screen — retry/decode-pending NEVER count as covered). REQ_IDs come ONLY from `allocReqId()` (return current, then increment; start at 1 per WS; if allocation would pass `0xFFFFFFFE`, reconnect and restart at 1 on the new WS — no-wrap is a call-site invariant, not prose). Coordinate ownership (frozen): needed → pending-network → received/decode-owned → cached; TILE receipt REMOVES pending immediately; overflow → `retryNeeded`; JPEG rejection → epoch-scoped `terminalFailed` in suppression; END resolves unreceived expected as server-skipped. FROZEN receive pipeline order — structural parse → wire-byte accounting → `classify(reqId)` → image/zoom/`expectedKeys` membership → duplicate check → `pending.delete` → THEN format/admission/decode interpretation (only a valid current-batch expected tile may touch `terminalFailed`; a stale/foreign FORMAT=2 frame can never poison the current epoch). FROZEN epoch cleanup on EVERY `newViewEpoch()` (pan/zoom/resize/switch alike — not just picker): clear old epoch's `retryNeeded` + `terminalFailed`, remove old-epoch `pending` entries, cancel old awaiters, purge queued decode payloads (a tile that terminal-failed in E is requestable again in E+1). Decode accepted iff mapped epoch === currentViewEpoch. Headroom gate + dynamic budget as v1.8; `avgTileBytes` uses the SAME wire-payload quantity as `rxBytes` and RESETS to the 128 KiB seed on every image switch (no cross-image staleness). WebSocket bootstrap (frozen): `new WebSocket(wsUrl, "ultratile.utp.v1")`, assert `ws.protocol === "ultratile.utp.v1"`, `ws.binaryType = "arraybuffer"`, await `open` before any UTP send. `viewer.js` duplicates four Java constants EXPLICITLY (`TILE=512`, `MAX_CACHE=40`, `MAX_TILE_BYTES=2097152`, `BATCH_CAP=30`) with a parity script pinning them to `Config.java`. `rxBytes` = UTP TILE `payloadLen` bytes received (JPEG payload only — NOT the 24B UTP header, NOT WS framing); `decodedBytes` = payload bytes that decoded (NOT bitmap footprint — report states the memory envelope separately). Picker uses `textContent`, never HTML interpolation.
- **REQ-007**: UTP/1.0 big-endian MAGIC `0xAA`, TILE_SIZE `512`, LOD `0` ONLY (nearest per frozen `selectLevel`; 1/2 reserved → reject), FORMAT `1` JPEG implemented (`2` WebP reserved: codec parses it, server never emits it, viewer treats it as terminal-unsupported-for-view); subprotocol `ultratile.utp.v1` REQUIRED on handshake (exactly one header — an UltraTile handshake-profile restriction stricter than RFC 6455's combinable list, labeled as such; server echoes it in 101, else 400); REQ_ID u32 no-wrap via `allocReqId()` (never reset on image switch, 1 only on new WS): `0x01` 28B `>BBHBBHIIIII` (freeze/mismatch-invalid/post-seal-rejected); `0x05` 8B `>BBHI` (three-way COMMIT as v1.8 — the newer-empty case installs sealed-empty `work=List.of()` through the SAME coalesced slot and the dispatcher sends its END; "immediate" means no tile work, never a reader-side END); `0x03` 8B `>BBHI` (cancel needs matching `(imageId,reqId)` — unknown ABORT ignored as stale, never advances seen; terminal, no END); `0x02` 24B `>BBHBBHIIII` (LEN u32 + ≤`MAX_TILE_BYTES`); `0x04` 16B `>BBHIII` (sealed/non-canceled/active/empty/inflight0 only). FROZEN stale-vs-invalid: STALE (ignore + WARNING, keep alive) = below-seen non-matching, unknown-ABORT, superseded non-active traffic, post-clear duplicates; INVALID (deterministic 1002 close, no hang) = chunk/COMMIT violating the CURRENT active generation (metadata mismatch, post-seal chunk, duplicate COMMIT while sealed) or COMMIT for a reqId in the bounded `rejectedReqIds` set; invalid-newer (fails validation, reqId > seen, touches no active state) = ignore + WARNING + record in `rejectedReqIds` (anti-poisoning preserved, connection alive). FROZEN rejected-set discipline (two v1.9 holes closed): (a) BEFORE accepting ANY new-generation chunk, test `rejectedReqIds.contains(reqId)` → 1002 (a bad-9 chunk can never be resurrected by a later valid-9 chunk; regression: bad-9 → valid-9 → 1002, active never becomes 9); (b) entries are purged ONLY once `id <= lastReqIdSeen` makes them permanently stale — live entries are NEVER FIFO-evicted (cap 64 covers the bad-100→valid-2 anti-poisoning test; a 65th live rejected ID closes the connection instead of evicting). Span≤128/packet; unique set ≤`GEN_TILE_CAP=256` with dedupe-aware check `if (!requested.contains(key) && requested.size()==GEN_TILE_CAP) reject` (a duplicate at cap stays accepted; only the 257th UNIQUE key rejects); validate-before-supersede as v1.8.
- **REQ-008**: dz/onetile import + direct n→Z + post-pad + tmp/validate/`.ready`/atomic-rename (immutable after); import START recovers leftover `.tmp-<id>`; CLI IDs decimal `0..65535` pre-path, all args quoted; ready target → no-op; non-ready numeric dir → `.stale-<id>-<epoch>/` quarantine; ignore `.tmp-*`/`.stale-*`. FROZEN canonical tile pathname `level-<Z>/<X>_<Y>.jpg` (PAT/REQ-008 normative — store, Java ingest, and the vips importer MUST agree; both importers tested against the store; the vips suffix form also pins the extension). - **REQ-009**: Dispatch on sealed READY SLOT (coalescing, never a FIFO) as v1.8 + teardown/wakeup (`closeSession` permit-release; dispatcher `closed`-check on wake) + frame-boundary cancel (channel is teardown-only) + stale-vs-invalid (1002) + `rejectedReqIds` (no-evict discipline); `transferTile` WS `24+fileSize` + looped `transferTo` with BOUNDED zero-progress fallback (≤3 consecutive `0` returns, then POSITIONAL `src.read(dst64k, transferredOffset)` advancing an explicit offset + `writeFully()` — `transferTo` never moves the channel position, so a plain `read()` would resend from the old position; EOF before the advertised length stays fatal); size gate pre-frame; SKIPPED pre-frame only; post-start fatal; `0x04` requires sealed && !canceled && `active.get()==state` && `nextIndex==work.size()` && `inFlight==0`. u32 discipline everywhere as v1.8.
