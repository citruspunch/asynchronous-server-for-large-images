Tiled image server, Java 21, custom protocol over WebSocket

The browser never fetches the image.

A source image can be tens of gigabytes, far too large to transfer or decode as one asset. UltraTile keeps the source on disk as a multiresolution pyramid of 512 by 512 JPEG tiles and sends only the tiles under the current viewport, at a resolution the browser can afford.

Normative wire behavior is defined by docs/protocol/UTP-1.0.md. This page is an explainer, not a specification.

01, Problem and system shape

Why the whole image can never be the unit of transfer

Downloading a multi-gigabyte raster would exhaust bandwidth, delay first paint, and overflow browser memory, mostly for pixels the user never looks at. The system therefore changes the unit of transfer from the image to the visible tiles at a bounded resolution.

The browser owns the only decoded bitmap cache. Per-session server cost does not grow with image dimensions.

03, UTP request lifecycle

Five messages, one generation

Three packet types travel up (client to server chunk, commit, abort) and two travel down (server to client tile, end). All fields are unsigned big endian. Select a packet to see exactly what crosses the wire, then step a generation. production rule for layouts and ordering.

04, Concurrency and streaming

Two threads per session, zero bytes of tile cache

The transport uses blocking I/O on Java 21 virtual threads, thread per session programming, not selector based nonblocking I/O. Tile bytes stream from FileChannel to the socket with no large intermediate copy, and per-session cost does not scale with image dimensions.

Session shape (one WebSocket)reader virtual thread dispatcher virtual thread
Socket readReader thread blocks on read, parses frames (1 KiB inbound cap) and validates UTP. Owns requested set until seal.
→
Sealed generationImmutable center first work list published at seal. One coalesced ready slot holds the newest sealed generation, so bursts collapse instead of forming a FIFO queue.
→
DispatcherOne thread per session, parked on a permit. Owns sent and skipped counts and the drain index.
→
Serialized writerOne ReentrantLock (pinning aware, not a monitor). Final admission is rechecked inside the lock before the first byte.
→
File to socketPositional transferTo loop, 64 KiB positional fallback after repeated zero progress. Frame declares 24 + fileSize up front.

Repeated requests reread tiles from disk. The JVM does not maintain a tile cache. Server memory per in-flight tile is a 24 byte header plus a 64 KiB fallback buffer only on the zero progress path. Per session it is two virtual thread stacks, a 1 KiB or smaller reassembly buffer, and 256 or fewer packed keys and work records.
The transport could be replaced without redesigning UTP. Tile store, packets, session rules, and viewer would be unchanged.

05, Browser resource pipeline

Backpressure before memory

Tiles move from needed to cached through a bounded pipeline. The viewer sends a batch only with decode headroom, sized from observed tile sizes.

Formula and headroom rule

planTileBytes = max(avgTileBytes, 64 KiB floor). budget = min(30, freeJobs, max(1, floor(freeBytes / planTileBytes))). The floor tames tiny synthetic tiles. Headroom needs in flight below 6, queued below 24, free bytes at least 2 MiB.

Scalable import, briefly

libvips reads image regions, never the whole raster, then publishes pyramid, padding, meta.json plus .ready by atomic rename. The Java ImageIO fallback decodes the whole image, so it is capped at 8192 px and 16 MP.

06, The decoded bitmap cache, LFUDA-40

Frequency with aging, not recency

Capacity is 40 decoded bitmaps. Each entry carries a frequency and a priority equal to age plus frequency. A global age watermark rises as evictions happen. Tilefreqpriorityprotected or pinnedadmission

insertion
frequency 1, priority age plus 1, stamped admission order. Admission is that epoch reference, so it is not counted twice.
reference
At most one per viewport epoch, tracked by lastCountedEpoch. Rendering uses peek() and never raises frequency.
victim
Lowest priority among eligible entries. Ties break by oldest admission. Recency is never stored or consulted.
aging
age is max(age, victim.priority). The max keeps a monotonic watermark under viewport protection. With no protection the victim is the global minimum and the rule is textbook LFUDA.
protection
Current viewport target and the z equal 0 overview pin decide who may be evicted. LFUDA decides who loses. Fallback tiers yield target protection, then pinning, rather than exceeding capacity. The just admitted tile is excluded from its own eviction.
eviction
Victim bitmap is explicitly close()d exactly once.
Naive LFU pins historically popular tiles forever, so one hot region blocks the region in view. Aging bleeds old popularity off. A hot tile never referenced again is eventually displaced. LRU would let redraws dominate. Frequency across viewport epochs measures useful reuse instead.
